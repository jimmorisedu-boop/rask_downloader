# Rask Downloader

Расширение для Chrome, которое добавляет кнопку скачивания на страницу проекта
в [app.rask.ai](https://app.rask.ai) и собирает готовый MP4 из **двух** дорожек
плеера: **картинка берётся из Original, звук — из Localized**.

Видеопоток копируется как есть (`-c copy`), без перекодирования, — качество
картинки остаётся ровно таким, каким было в исходном файле. Вся работа идёт
локально в браузере: ffmpeg вкомпилирован в расширение, ничего никуда не
отправляется.

## Зачем это нужно

На странице проекта Rask плеер показывает две версии ролика, переключаемые
тумблером **Original / Localized**. Это два независимых MP4-файла: в первом
исходная картинка и исходный звук, во втором — результат локализации.

Расширение берёт из них ровно то, что нужно: видеодорожку из первого файла и
аудиодорожку из второго, и склеивает в один MP4 без перекодирования видео.

---

## Что умеет

Панель появляется справа внизу на странице проекта.

| Кнопка | Что делает | Результат |
| --- | --- | --- |
| **Скачать видео** | видео из Original + звук из Localized, склейка в браузере | `<проект>.mp4` |
| Только Original | скачивает исходный файл как есть | `<проект>.original.mp4` |
| Только Localized | скачивает локализованный файл как есть | `<проект>.localized.mp4` |
| Два файла + .bat | качает оба MP4 и скрипт для локального ffmpeg | папка `Rask/<проект>-<дата>/` |

Последние три спрятаны под ссылкой «Другие варианты».

Режим **«Два файла + .bat»** нужен для очень больших роликов: ffmpeg.wasm
32-битный и примерно от 2 ГБ упирается в лимит адресного пространства. Если на
машине установлен обычный ffmpeg, `.bat` сделает ту же склейку без ограничений
по размеру. Все три файла кладутся в отдельную папку с датой в имени — иначе
Chrome при совпадении имён переименовал бы файл (`video.mp4` → `video (1).mp4`)
и пути внутри `.bat` перестали бы совпадать.

## Установка

Расширение самодостаточное: ни сборки, ни npm, ни отдельно установленного
ffmpeg для основного режима не требуется.

### Вариант 1 — из архива

1. Скачать `rask-downloader.zip` и распаковать в любую постоянную папку.
   Не удаляйте её потом: Chrome загружает распакованное расширение по пути,
   а не копирует к себе.
2. Открыть `chrome://extensions` (в Edge — `edge://extensions`).
3. Включить **Режим разработчика** (переключатель справа вверху).
4. Нажать **Загрузить распакованное расширение** и выбрать папку
   `rask-downloader` — ту, внутри которой лежит `manifest.json`.

### Вариант 2 — из исходников

```bash
git clone https://github.com/jimmorisedu-boop/rask_downloader.git
```

Дальше те же шаги 2–4, папка — корень репозитория.

### Проверка, что встало

В списке расширений должна появиться карточка **Rask Downloader** без красной
плашки с ошибками. Если плашка есть — нажмите на неё, текст ошибки подскажет,
чего не хватает (чаще всего папку выбрали на уровень выше или ниже нужного).

## Как пользоваться

1. Залогиньтесь в Rask и откройте страницу проекта, например
   `https://app.rask.ai/spaces/<space-id>/project/<project-id>`.
2. Дождитесь, пока прогрузится плеер с тумблером Original / Localized. Панель
   расширения появляется только когда на странице есть и плеер, и тумблер.
3. Нажмите **Скачать видео**.
4. Панель коротко покажет «Читаю дорожку Original… / Localized…» — в этот момент
   она переключает плеер, чтобы снять обе ссылки, и возвращает его в исходное
   состояние.
5. Откроется новая вкладка со склейкой: прогресс по шагам, полоса выполнения и
   раскрывающийся лог ffmpeg. Закрывать её до конца не нужно.
6. Готовый файл уедет в папку загрузок.

Первый запуск дольше остальных: подгружается ядро ffmpeg (~32 МБ) из папки
расширения. Дальше оно кешируется браузером.

## Как это устроено

### Разведка: откуда берутся ссылки

Плеер Rask — обычный HTML-элемент `<video>`. Тумблер Original / Localized просто
подменяет у него `src` на подписанную ссылку вида:

```
https://app.rask.ai/data/<project-id>/<asset-id>.mp4?X-Amz-Algorithm=…&X-Amz-Signature=…
```

Ни HLS, ни DASH, ни DRM здесь нет — это цельные MP4-файлы, отдаваемые по
presigned-ссылке S3 через домен Rask. Поэтому достаточно забрать два URL и
склеить файлы; расшифровывать или пересобирать сегменты не требуется.

### Определение дорожек

Ключевая деталь: расширение **не угадывает**, какой `asset-id` относится к
оригиналу, а какой к локализации, и не парсит внутренний API (его формат может
поменяться в любой момент). Вместо этого `content.js`:

1. Запоминает текущий `src` и состояние плеера (позицию, играет или на паузе).
2. Кликает по кнопке **Original**, ждёт, пока `src` сменится, и записывает ссылку.
3. Кликает по кнопке **Localized**, делает то же самое.
4. Возвращает плеер на ту дорожку, что была открыта изначально, и восстанавливает
   позицию воспроизведения.

Так соответствие «ссылка → дорожка» получается точным по построению. Если
дорожка уже была активна и `src` не менялся, шаг просто отдаёт текущую ссылку.

Кнопки ищутся по подписям (`Original` / `Localized`, плюс русские варианты
«Оригинал», «Локализ…», «Дублированное»). Если Rask переверстает интерфейс или
сменит язык, срабатывает запасной поиск: группа ровно из двух кнопок в пределах
восьми уровней родителей от `<video>`.

### Поток данных

```
┌─────────────────────────────┐
│ app.rask.ai (страница)      │
│                             │
│  content.js                 │  1. находит <video> и тумблер
│   ├ рисует панель в Shadow  │  2. кликает Original → URL_v
│   │  DOM (стили страницы    │  3. кликает Localized → URL_a
│   │  не задевает)           │  4. восстанавливает плеер
│   └ sendMessage ────────────┼──┐
└─────────────────────────────┘  │
                                 ▼
                    ┌────────────────────────────┐
                    │ background.js (SW)         │
                    │  кладёт задание в          │
                    │  chrome.storage.session    │
                    │  открывает вкладку         │
                    └────────────┬───────────────┘
                                 ▼
                    ┌────────────────────────────┐
                    │ mux.html + mux.js          │
                    │  fetch URL_v ──► байты     │
                    │  fetch URL_a ──► байты     │
                    │  ffmpeg.wasm (vendor/)     │
                    │  chrome.downloads.download │
                    └────────────────────────────┘
```

Почему склейка вынесена в отдельную вкладку, а не делается прямо в контент-скрипте:

- **CSP.** WebAssembly требует директиву `wasm-unsafe-eval`. У страниц расширения
  свой Content-Security-Policy, который мы контролируем в манифесте; на CSP
  чужого сайта повлиять нельзя.
- **Живучесть.** Service worker в Manifest V3 засыпает через ~30 секунд простоя,
  а склейка длинного ролика идёт дольше. Обычная вкладка не засыпает.
- **Кросс-доменный fetch.** Страница расширения с `host_permissions` может
  скачать файл с `app.rask.ai` напрямую, без ограничений CORS.
- **Наглядность.** Видно прогресс, и лог ffmpeg под рукой, если что-то пошло не так.

Подписанные ссылки передаются через `chrome.storage.session`, а не через
параметры URL, — так они не попадают ни в адресную строку, ни в историю
браузера. После успешного завершения задание из хранилища удаляется.

### Склейка

```
ffmpeg -i video_src.mp4 -i audio_src.mp4 \
       -map 0:v:0 -map 1:a:0 \
       -c copy -movflags +faststart out.mp4
```

| Флаг | Что делает |
| --- | --- |
| `-i video_src.mp4` | вход №0 — файл Original |
| `-i audio_src.mp4` | вход №1 — файл Localized |
| `-map 0:v:0` | взять первую видеодорожку из входа 0 |
| `-map 1:a:0` | взять первую аудиодорожку из входа 1 |
| `-c copy` | копировать потоки байт-в-байт, не перекодировать |
| `-movflags +faststart` | перенести индекс `moov` в начало файла, чтобы видео начинало играть без полной загрузки |

Аудиодорожка Original и видеодорожка Localized в результат не попадают вовсе —
они просто не выбраны в `-map`.

Если по какой-то причине звук не удаётся положить в MP4-контейнер копированием,
идёт второй проход с `-c:v copy -c:a aac -b:a 192k`. Видео и в этом случае
копируется без перекодирования — меняется только звук. В логе такой переход
отмечен строкой `--- копирование звука не прошло, перекодирую в AAC ---`.

## Структура проекта

| Файл | Роль |
| --- | --- |
| `manifest.json` | манифест MV3: разрешения, контент-скрипт, CSP страниц расширения |
| `content.js` | работает на app.rask.ai: находит плеер и тумблер, снимает обе ссылки, рисует панель |
| `background.js` | service worker: принимает задание, кладёт в `storage.session`, открывает вкладку склейки |
| `mux.html` | интерфейс вкладки склейки: шаги, прогресс, лог |
| `mux.js` | скачивание файлов, вызов ffmpeg.wasm, сохранение результата, генерация `.bat` |
| `popup.html` / `popup.js` | всплывающее окно по клику на иконку: краткая справка и статус вкладки |
| `icons/` | иконки 16 / 48 / 128 px |
| `vendor/` | ffmpeg.wasm (см. ниже) |

Панель на странице живёт в **Shadow DOM**, поэтому её стили не пересекаются со
стилями Rask, а стили Rask не ломают панель. За тем, что панель не пропала после
перерисовки React, следит `MutationObserver` плюс страховочный таймер.

### Что лежит в `vendor/`

ffmpeg.wasm, вкомпилированный в расширение, потому что Manifest V3 запрещает
подгрузку удалённого кода:

| Файл | Origin | Размер |
| --- | --- | --- |
| `ffmpeg.js` | `@ffmpeg/ffmpeg` 0.12.15, сборка umd | 4 КБ |
| `814.ffmpeg.js` | воркер из того же пакета | 3 КБ |
| `ffmpeg-core.js` | `@ffmpeg/core` 0.12.10, сборка umd | 112 КБ |
| `ffmpeg-core.wasm` | ядро ffmpeg | 32 МБ |

Относительно оригинальных пакетов сделаны две правки:

1. В `814.ffmpeg.js` дефолтная ссылка на ядро заменена с
   `https://unpkg.com/@ffmpeg/core@0.12.9/…` на локальную `./ffmpeg-core.js`.
   Мы и так передаём `coreURL` явно, но так исключён любой шанс обращения в сеть.
2. Убраны комментарии `sourceMappingURL` — `.map`-файлы в поставку не входят, и
   без правки в DevTools сыпались бы 404.

Важная деталь для тех, кто будет обновлять vendor: воркер **должен** создаваться
как классический, а не как ES-модуль. Внутри он использует `importScripts()`,
которого в module-воркерах нет. Поэтому в `mux.js` опция `classWorkerURL`
намеренно **не** передаётся — обёртка сама находит `814.ffmpeg.js` рядом с
`ffmpeg.js` и запускает его классическим воркером.

## Разрешения

| Разрешение | Зачем |
| --- | --- |
| `downloads` | сохранить готовый файл в папку загрузок |
| `storage` | передать задание из контент-скрипта во вкладку склейки через `storage.session` |
| `host_permissions: https://app.rask.ai/*` | работать на страницах Rask и скачивать оттуда файлы |

Доступа к другим сайтам, истории, вкладкам или закладкам расширение не просит.

---

## Приватность

- Никаких внешних серверов: ни аналитики, ни телеметрии, ни обращений куда-либо,
  кроме самого `app.rask.ai`.
- ffmpeg работает локально, внутри браузера. Видео никуда не загружается.
- Подписанные ссылки хранятся в `chrome.storage.session` (живёт до перезапуска
  браузера) и удаляются сразу после успешной склейки.
- Расширение не логинится и не обходит доступ: оно работает только в уже
  авторизованной сессии и берёт ровно те файлы, которые плеер и так отдаёт в
  браузер.

## Проверить результат самому

Если хочется убедиться, что картинка действительно взята из Original, а звук из
Localized, — скачайте оба исходника (кнопки «Только Original» и «Только
Localized») и сравните декодированные дорожки по контрольной сумме:

```bash
ffmpeg -v error -i proekt.original.mp4  -map 0:v -f md5 -   # видео оригинала
ffmpeg -v error -i proekt.mp4           -map 0:v -f md5 -   # видео результата → должны совпасть

ffmpeg -v error -i proekt.localized.mp4 -map 0:a -f md5 -   # звук локализации
ffmpeg -v error -i proekt.mp4           -map 0:a -f md5 -   # звук результата → должны совпасть
```

Совпадение видео-хешей означает, что перекодирования не было вообще: поток
скопирован байт-в-байт.

## Диагностика

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Панель не появилась | страница ещё грузится, или на ней нет плеера с тумблером | дождаться загрузки плеера; проверить, что это страница проекта, а не список проектов |
| «Не найден переключатель Original / Localized» | вёрстка Rask изменилась | открыть issue; временно помогут кнопки «Только Original / Localized» |
| «Не удалось прочитать ссылки на видео» | плеер ещё не подставил `src` | нажать Play в плеере и повторить |
| «Сервер вернул 403» | подписанная ссылка протухла (живёт около часа) | обновить страницу Rask (F5) и нажать кнопку заново |
| «Original и Localized дали одну ссылку» | клик по тумблеру не переключил дорожку | переключить тумблер вручную, убедиться, что видео меняется, и повторить |
| Вкладка склейки падает на длинном ролике | ffmpeg.wasm исчерпал память | использовать режим «Два файла + .bat» |
| Склейка идёт очень долго | первый запуск грузит ядро 32 МБ | подождать; дальше ядро берётся из кеша |
| В логе появился переход на AAC | звук не лёг в контейнер копированием | это штатный запасной путь, видео всё равно не перекодировано |

Полезные места, куда смотреть при разборе: лог ffmpeg внизу вкладки склейки,
консоль страницы Rask (сообщения с префиксом `[Rask DL]`) и консоль service
worker на `chrome://extensions`.

## Ограничения

- **Ссылки живут около часа.** Если вкладка Rask провисела дольше, обновите её
  перед скачиванием, иначе на этапе загрузки прилетит 403.
- **Память.** ffmpeg.wasm 32-битный: примерно от 2 ГБ исходников упирается в
  лимит адресного пространства. Для таких роликов есть режим с `.bat`.
- **Оба файла сначала грузятся в память целиком.** Для длинных роликов это
  заметный расход RAM во вкладке склейки.
- **Привязка к вёрстке.** Тумблер ищется по подписям и по структуре; редизайн
  Rask может потребовать правки селекторов в `content.js`.
- **Только страница проекта.** Внутри редактора (`Open editor`) панель не
  появляется — там другой плеер.

## Пересборка vendor из npm

Если нужно обновить ffmpeg:

```bash
npm install @ffmpeg/ffmpeg@0.12.15 @ffmpeg/core@0.12.10

cp node_modules/@ffmpeg/ffmpeg/dist/umd/ffmpeg.js      vendor/
cp node_modules/@ffmpeg/ffmpeg/dist/umd/814.ffmpeg.js  vendor/
cp node_modules/@ffmpeg/core/dist/umd/ffmpeg-core.js   vendor/
cp node_modules/@ffmpeg/core/dist/umd/ffmpeg-core.wasm vendor/
```

После копирования обязательно повторите обе правки из раздела
[«Что лежит в vendor/»](#что-лежит-в-vendor): замену ссылки на unpkg и удаление
`sourceMappingURL`. Проверить, что не осталось обращений в сеть:

```bash
grep -o "https\?://[a-zA-Z0-9./@_-]*" vendor/*.js
```

В выводе не должно быть ничего, кроме ссылки на документацию Emscripten внутри
`ffmpeg-core.js` (она в комментарии и никуда не запрашивается).

## Совместимость

- Chrome 102 и новее — нужен `chrome.storage.session`.
- Любой браузер на Chromium с Manifest V3: Edge, Brave, Opera, Vivaldi.
- Firefox не поддерживается: там другой формат манифеста и нет `storage.session`
  в том же виде.
- Хостовая ОС значения не имеет; `.bat` из режима «Два файла + .bat» рассчитан
  на Windows, но команда внутри него одинакова для всех систем.

## Лицензии

| Компонент | Лицензия |

| `@ffmpeg/ffmpeg` 0.12.15 (`vendor/ffmpeg.js`, `vendor/814.ffmpeg.js`) | MIT |
| `@ffmpeg/core` 0.12.10 (`vendor/ffmpeg-core.js`, `vendor/ffmpeg-core.wasm`) | **GPL-2.0-or-later** |
| Код расширения (`content.js`, `background.js`, `mux.js`, `popup.js`) | не выбрана, см. ниже |

Существенный момент: ядро ffmpeg в `vendor/` распространяется под
**GPL-2.0-or-later**, и оно вкомпилировано прямо в расширение. Как только
расширение передаётся кому-то ещё — архивом, ссылкой на репозиторий или через
магазин, — это распространение производного произведения, и на всю сборку
